# TwiXP

### Twitch-чат, который работает там, где не должен

Windows XP. Eee PC 701. Celeron ULV на ~630 МГц. Ни один современный
чат-клиент даже не запустится на такой машине — а этот не просто
запускается, а летает.

TwiXP — нативный, написанный с нуля под это железо Twitch-чат клиент.
Никакого Electron, никакого браузерного движка внутри, никакого "ну
просто на 2 ГБ ОЗУ хватит". Чистый Win32 GUI и собственный рендеринг
текста, который считает каждый мегабайт и каждый такт CPU так, будто
на дворе 2003 год — потому что для этой машины так оно и есть.

## Зачем это вообще существует

Потому что хочется смотреть чат стрима, пока рядом пылится нетбук из
2007-го, а не потому что "а вдруг получится". Каждая деталь в этом
проекте — результат столкновения с тем, что на современном железе
просто не заметно: перерисовка, съедающая заметный процент CPU на
слабом Celeron; готовые текстовые контролы Windows, которые либо не
умеют того что нужно, либо стоят слишком дорого; библиотека GUI,
последний раз обновлявшаяся до появления многих привычных вещей в Go.
Ничего из этого не остановило — местами пришлось спорить с самой
Windows на уровне сырых сообщений `WM_*`, и в итоге всё работает.

## Что умеет

- **Вход одним кодом** — Twitch Device Code Flow: показал код на
  экране, подтвердил на телефоне, готово. Ни пароля, ни консоли.
- **Сколько угодно каналов разом** — список слева, у каждого своя
  история, копится в фоне даже пока смотришь другой чат.
- **Живой чат, а не только текст**: ответы, системные уведомления о
  подписках/рейдах/объявлениях с уже готовым текстом от самого Twitch,
  сообщения, выделенные за баллы канала — с той же лиловой полосой
  слева, что и в вебе.
- **Бейджи с иконками** — глобальные и канальные, подгружаются на лету.
- **Тебя упомянули — сразу видно**: едва красная подсветка строки.
- **Автодополнение `@никнейм`** — всплывающий список над полем ввода,
  стрелки и мышь, как в нормальном мессенджере, только это XP.
- **Тонкая настройка под себя**: время, бейджи, аватарки, подсветка,
  автодополнение, размер шрифта, окно поверх всех — всё переключается
  на лету, без перезапуска.
- **Само переподключается**, когда рвётся сеть или Twitch просит
  переехать на новую сессию — просто продолжает работать.

## Инженерная начинка (для тех, кому это тоже интересно)

- История чата — не текстовое поле, а **полностью свой рендер** поверх
  голого `CustomWidget`: свой перенос строк, свой скролл, свой кэш
  раскладки на каждое сообщение, чтобы не пересчитывать геометрию на
  каждый кадр.
- Там, где `lxn/walk` бессилен — сырой Win32 напрямую: нативная
  утопленная 3D-рамка через `WS_EX_CLIENTEDGE`, подавление мерцания на
  `WM_ERASEBKGND`, а всплывающий попап автодополнения — это буквально
  системный `LISTBOX`, поднятый как отдельное окно и управляемый
  вручную, потому что готового виджета для этого попросту нет.
- Собирается **настоящим Go 1.10.8** на запиненных до 24 августа
  2018 года коммитах `lxn/walk`/`lxn/win` — последних, что ещё дружат
  с этой версией компилятора.

## Сборка

Ядро (`internal/domain`, `internal/app`, `internal/infra`) — обычный
современный Go-модуль, от GUI не зависит:

```sh
make vet-core   # go vet по ядру
make test       # go test по ядру — пока покрыт только domain
make fmt        # список неотформатированных файлов
```

Оба таргета гоняются на каждый push/PR (см. `.github/workflows/ci.yml`) —
без Windows, без GOPATH, без Go 1.10.8: обычный `go test` на обычном
Go-модуле.

Сам клиент (`main.go`, `internal/ui`) живёт в отдельном GOPATH-стиль
окружении (`GO111MODULE=off`) с запиненными зависимостями:

```sh
make deps    # один раз стягивает lxn/walk, lxn/win, govaluate.v3
make check   # быстрая проверка сборки текущим Go под GOOS=windows
make build   # финальная сборка настоящим Go 1.10.8 → bin/twixp.exe
```

`make build` требует настоящий Go 1.10.8 в `PATH` под именем
`go1.10.8` (или свой путь через `make build GO_XP=...`):

```sh
go install golang.org/dl/go1.10.8@latest
go1.10.8 download
```

Без него — только `make check`: собирает современным Go под
`GOOS=windows/386`, годится проверить компиляцию, но не заменяет
финальную сборку (1.10.8 может не принять то, что современный Go
пропустит молча).

## Первый запуск

Перед первой сборкой скопируйте `config.go.example` в `config.go` и
впишите туда свой Twitch Client ID (`const clientID`) — зарегистрировать
приложение и получить его можно на
[dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps).
`config.go` не хранится в репозитории (см. `.gitignore`) — у каждой
сборки должен быть свой Client ID. Client secret не нужен вообще —
Device Code Flow работает без него.

```sh
cp config.go.example config.go
```

При первом запуске приложение покажет код и ссылку
(`https://www.twitch.tv/activate`). Подтвердили на телефоне или другом
компьютере — токен лёг в `data/state.json`, дальше вход тихий.

## Релизы

`.github/workflows/release.yml` собирает `twixp.exe` и публикует его
на странице Releases по push git-тега вида `vX.Y.Z`:

```sh
git tag v1.2.0
git push origin v1.2.0
```

Версия в коде нигде не хранится — источник истины сам тег, релиз-ноты
генерирует GitHub из списка коммитов/PR с прошлого тега. Один раз
перед первым релизом нужно завести secret в самом репозитории —
Settings → Secrets and variables → Actions → New repository secret →
`TWITCH_CLIENT_ID`, значение — то же, что в вашем локальном
`config.go`: CI не может прочитать ваш незакоммиченный файл и берёт
Client ID оттуда.

## Структура проекта

```
internal/domain   — чистые типы данных (Channel, User, ChatMessage, Settings...)
internal/app      — сценарии поверх domain (авторизация, отправка/чтение чата)
internal/infra    — Twitch Helix/EventSub, хранилище на диске, TLS
internal/ui       — вся отрисовка и виджеты (lxn/walk + сырой win32)
```
